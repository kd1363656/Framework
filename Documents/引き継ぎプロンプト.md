### 状況
- ビルドは通り、`runall.py` も基準値どおり(2026-10-10 夜)。起動はできた。**終了時だけ**アサートが出ている。
- 起動中の見た目は確認できていない(モデルを描画申請に登録するコンポーネントがまだ無いため、モデルは描かれない)。

  文言を読めば原因の見当が付くはずなので、まずそれを確認する。

### 原因の見当(まだ確かめていない仮説。決め付けず、コードで確かめる)
1. **破棄順:** 今回、`ModelMaterialSystem` が GPU のバッファ(`ModelMaterialGPUTable` ×2)を持つようになった。
   - `ModelMaterialGPUTable` のデストラクタは `Release()` で、`ResourceReleaseContext` への**遅延解放の予約**をするだけ。
   - 終了時に、予約したものを実際に解放する前に `GPUMemoryAllocator`(D3D12MA の Allocator)が破棄されると、
     「解放されていない Allocation が残っている」というアサート / 警告になりうる。
   - `ResourceContext` のメンバの宣言順(= 破棄順の逆)と、終了時に `ResourceReleaseContext` を全部解放する処理があるかを確認する。
2. **エラーマテリアル:** `ModelMaterialSystem::m_errorMaterial` が持つ `Texture`(既定テクスチャを指すハンドル)の破棄が、
   `TextureSystem` / `ResourceReleaseContext` / `GPUMemoryAllocator` の破棄より後になっていないか。
   (マテリアルの `Texture` は、破棄時に `TextureSystem` を引いて参照数を減らす。引く先が先に破棄されているとまずい。)
3. **既存の StructuredBuffer との違い:** 既存の `StaticStructuredBuffer` などは、Record が `AssetStorage` に入っていて、
   終了時の解放の流れ(`ReleaseCompletedDeferredResources` など)に乗っている。
   `ModelMaterialGPUTable` はその流れに乗っていない(`ModelMaterialSystem` の `shared_ptr` メンバ)ので、同じ扱いになっているか確認する。
4. **A1-3-1 より前から出ていたか:** `git stash` などで A1-3-1 の変更を外して終了時のアサートの有無を確かめると切り分けられる
   (ただしユーザーの未コミットの変更を壊さないよう、必ずユーザーに確認してから行う)。

### 直し方の方針
- 原因が破棄順なら、`ResourceContext` のメンバの宣言順を直す(依存される側を先に宣言する = 後に破棄される)。
- 終了時に遅延解放の予約が残るなら、終了処理で `ResourceReleaseContext` を強制的に全部解放する流れに乗せる。
- 直したら、**起動 → × ボタンで終了**で、アサートが出ないことをユーザーに確認してもらう(自分では確認できない)。

### 2-4. 規約の要点(詳細は CodingConventions.txt)
- **接頭辞:** `l_` / `a_` / `m_` / `k_`
- **取得関数:**
  - `GetREF` / `GetMutableREF` / `GetVAL`
  - `Fetch` / `Find` は VAL / PTR / REF を付ける
  - Setter の引数名は `a_set`
  - bool を返す関数は Is / Can / Has で始める(Contains は使わない)
  - 出力引数に渡すときは `GetMutableREF` を使う(const の Get を渡して C2664 になったことがある)
  - Set で済む値の設定に `GetMutableREF` を使わない。読むだけなら `GetREF`(6-4。子の処理を呼ぶ・処理クラスが持ち主を加工する・TypeINFO 付きの差し替え・エディターの状態は例外)
  - 自作の関数の戻り値に、続けて関数やメンバを書かない(`a.GetREFModelData().m_meshList` は NG、1段ずつ変数で受ける)。`GetVAL().lock()` だけは可。std / ImGui / Jolt の戻り値は対象外(11-11)
  - 本体が if だけの for 文は書かず、`std::ranges::all_of` / `find_if` / `std::views::filter` / `transform` + `erase_if` にする(11-9)
- **ヘッダーの並び順:**
  - 処理 → Is/Can/Has → Apply → Set → Fetch/Find → GetREF …
  - private は関数 → 定数 → メンバ
  - メンバは配列 → ポインタ → 値(20-2)
- **縦揃え:**
  - `=` と最初の `(` を揃える。
  - 呼び出しだけの行が続くときも、最初の `(` を揃える。
  - FWK_ASSERT のメッセージと後ろの引数は**表示幅**で揃える(全角は2と数える)。
  - 定数グループでは符号(+/-)の位置も揃える。
- **その他の規則:**
  - そのif文の中でしか使わない値は、if の初期化文に書く(9-6)。
  - `std::tuple` は使わない。
  - 構造体はクラスの public 入れ子にしない。`Definition/Struct` に置く。
  - 構造体の継承はしない。
  - 構造体のメンバに持ち主の型名を繰り返さない(例: Model 構造体のメンバは `m_modelMeshList` ではなく `m_meshList`)。
  - 複数のクラスで共通の処理は「最初に使うクラス名 + Utility.h」というヘッダーにまとめる。
  - ヘッダーの関数の外側にはコメントを書かない。クラスの説明は .cpp の先頭、メンバや定数の説明は使う処理の中に書く(マクロの説明だけは例外)。
  - 8バイト以上の値は参照か `const auto&` で受ける。
  - auto は、ヘッダーの定義やリテラル初期化では型名を書き、右辺の型が決まっているときは auto にする。
  - スマートポインタの引数は基本 weak_ptr。所有を共有・保持するものだけ shared_ptr にする。
  - マジックナンバーは `Definition/Constant/...` の定数にする。
- **シリアライズ:** `XxxJsonConverter` を `Converter/Json/` に置く。バイナリは `XxxBinaryConverter`(`Converter/Binary/`)。

  モデルを設定したとき(と取り込み直したとき)に1回だけ、名前でスロットの一覧を作る。
  名前が見つからないスロットはエラーマテリアル(マゼンタ)。余った組は捨てずに JSON に残す。
  (Unity は `sharedMaterials[i]`、Unreal は StaticMaterials のスロット名 + MaterialIndex と同じ考え方。)
- **登録のタイミング:** 毎フレーム「描いてよいか」を調べない。状態が変わった時(SetModel / モデルの GPU 転送完了 / マテリアル変更 / 有効・無効 / 破棄)にだけ判断し、
  描画リストには「描ける」と確定したものだけを入れる。ModelComponent をステートパターン(未設定 → 転送待ち → 描画可能)にする案。
  転送完了は、モデルシステムが待っているコンポーネントへ通知する(推奨案 A)。
- **`m_canDraw`:** 描画申請データ(オブジェクト)単位。描画ループで lock の直後に見て、false なら書き込みも DispatchMesh もしない。
- **lock は必須。** 参照が消えたら自動で描画リストから外れるようにする(ユーザー指示)。
- **パスへの振り分け:** 複数のマテリアルを管理するクラスが `std::unordered_map<StaticTypeID, std::vector<スロット番号>>` を持つ。
  **引くのは登録時だけ**(描画時には引かない)。パスは受け取った番号リストを回すだけにする。
- **パス参加の決め方:** 見た目のパス(Lit / UnLit / Toon の本体、アウトライン)はマテリアルが決める。
  影・深度のような形だけのパスはオブジェクト(コンポーネント)が決める(マテリアルからも外せる)。最終的な参加 = シェーダーが持つ ∧ マテリアルで有効 ∧ オブジェクトで有効。登録時に1回だけ計算する。
- **PSO の切り替えは重い**ので、同じ PSO で描くものをまとめる(種類ごとのパスにまとめる)。マテリアルはシェーダーそのものを持たず、種類(TypeINFO)だけを持つ。

### ExecuteIndirect(A1-3-2 の後、すぐ実装する)
- データの形は A1-3-1 の B 案(種類ごとのテーブル)のまま、ExecuteIndirect を足す。
- 必要なもの: オブジェクトのテーブル(全オブジェクトの行列を並べた StructuredBuffer)、パスごとの描画項目のテーブル(どのオブジェクトの・どのメッシュを・どのマテリアルで)、
  コマンドシグネチャ(ルート定数 + DispatchMesh の引数)、引数のバッファ。最初は CPU が登録の変化時に作る。将来はコンピュートシェーダーでカリングして詰める(GPU 駆動)。
- 描画は、パスごとに「SetPipelineState → ルートの設定 → ExecuteIndirect 1回」になる。DirectX 12 の API を触るので、コメントと説明を特に詳しくすること。

## 4. 注意点(前のセッションで失敗したこと)

- **一括置換スクリプトの落とし穴:**
  - `\b` は日本語を単語の文字として扱うので、識別子の直後に日本語が続くと置換漏れになる。
  - 縦揃えの修正で、2つ目の `(` まで揃えてしまう(`.clear     ();`)ミスがあった。揃えるのは最初の `(` だけ。
- **reorder.py の分類:** friend / using / 入れ子の型 / `operator=` / `alignas` 付きのメンバ / マクロを誤って分類したことがある。並べ替えた後は必ずビルドして差分を確認する。
- **FWK_ASSERT の揃え:** 文字数ではなく表示幅で揃える。
- **ユーザーが仕様を言い直すことがある:** 例えば位置キーは int64 → Vector3 → int64 → **Vector3 + std::round(最終)** と変わった。最後の指示に従い、説明では今の状態だけを書く。
- **Skeletal のフィルター:** Skeletal 関連のファイルを追加するときは、フィルター名の綴りを特に確認する。
- **CRLF の確認:** Bash で `grep -c $'\r$'` を使うと0件と出ることがあるので、`grep -c $'\r'` で数える。
- **HLSL(.hlsl / .hlsli)も BOM 付き UTF-8 / CRLF / 末尾改行なし。** Python で置換するときは `\n` を `\r\n` に変えてから探す(変えないと見つからない)。
- **GraphicsCONFIG.json も BOM 付き UTF-8 / CRLF。** Python の `json` で読み込み、`indent=4, ensure_ascii=False, sort_keys=True` で書き出すと元と同じ形式になる(書き換える前に、読み込んで書き出した結果が元と同じか確かめる)。
- **`errs.py` は `PYTHONIOENCODING=utf-8` を付けて実行する**(付けないと日本語のエラーで落ちる)。
- **ヒアドキュメントに `\n` や `\r` を含む Python を書かない。** 改行に化けてスクリプトが壊れる。Write ツールでファイルに書いてから実行する。
  (今回も、ヒアドキュメントで書いた置換スクリプトが何度か壊れた。)
- **自動修正スクリプトの限界:** `chainfix.py`(連続呼び出しの自動修正)は、if の初期化文・`&&` の後ろ・マクロ・名前の重複・`GetREFXxx ()` のように `(` の前に空白がある既存の宣言は直せない。手で直す。
- **D3D12 のバッファは、コマンドリストの実行が終わるたびに COMMON の状態へ戻る(状態の減衰)。** `ModelMaterialGPUTable` はこれを前提に、毎フレーム COMMON から遷移している。
