1.ファイルについて===========================================================================================================================================
・ファイル名はアッパーキャメルケースで書き、クラス名と同じにする(.hと.cppは同じ名前)
{
	例↓
	AudioManager.h
	AudioManager.cpp
}
・文字コードはBOM付きUTF-8、改行コードはCRLF
・インデントはスペース4つ(タブは使わない)
・ファイルの最終行に改行を入れない
{
	理 : 不要な空行ができるのを防ぐため
	例↓
	class Hoge final
	{
		～処理～
	};
	←改行なしで終わる
}
・テンプレート(関数・クラス・メンバ関数)は必ずヘッダーに定義を書く(.cppには書かない)
{
	理 : テンプレートは使った型・値ごとにコンパイラーが関数を作るため、使う場所から定義が見えている必要がある
	     .cppに書くと、そこ以外から使ったときにリンクエラーになる

	テンプレートの中は短くし、型・値に関係ない処理はテンプレートでない関数にして.cppへ書く
	例↓ CreateRegisteredAssetFile<RegistryType>(ヘッダー)の中で、RegisterNewAssetFile / CancelNewAssetFile(.cpp)を呼ぶ
}
・ヘッダーの1行目は必ず#pragma once
・空行は2行以上続けない
・行末に空白を残さない
・置き場所
{
	クラス                   : そのクラスの機能のフォルダ(Audio/、Graphics/Command/Queue/ など)
	Jsonの変換クラス         : 変換したいクラスのフォルダ/Converter/Json/
	定数                     : Definition/Constant/<機能>/<クラス名>Constant.h
	構造体                   : Definition/Struct/<機能>/<クラス名>Struct.h
	Enum                     : Definition/Enum/<機能>/
	コンセプト               : Definition/Concept/
	マクロ                   : Definition/Macros/
	型エイリアス・型トレイト : Definition/Type/Alias/、Definition/Type/Trait/
	共通処理                 : Utility/<機能>/<名前>Utility.h

	1ファイルだけのために下位フォルダは作らない
}
2.省略形の名前について=======================================================================================================================================
・省略形の名前を書く際はすべて大文字にする(jsonのキー文字には適用しない)
{
	アッパーキャメルケースの場合
	PCH
	WindowCONFIG;

	ロウワーキャメルケースの場合
	pch
	windowCONFIG;

	よく使うもの↓
	INIT、CONFIG、REF、PTR、VAL、UUID、INFO(TypeINFO)、MIN、MAX、NUM、FPS、IMGUI、SRV、UAV、CB、VB、IB、GPU、CPU、FBX
}
3.インクルードについて=======================================================================================================================================
・.cppの1行目は自分のヘッダーのインクルードだけを書く
{
	理 : 他のヘッダーはPCH.hとFramework.hにまとめてあるので.cppで個別にインクルードする必要がないから

	例↓
	#include "AudioManager.h"

	FWK::AudioManager::AudioManager() :
	...
}
・新しくヘッダーを作ったらFramework.hにインクルードを追加する
・プリコンパイル済みヘッダーではインクルードしたものが関係の深いものなら隣接して#include文を書き
そうでなければ1行、行間を開けて書く
コメントでインクルードしているものについて書く
{
	理 : 何をインクルードしているのか分かりやすいようにするため、
	コメントは索引として書く

	例↓
	//================================================
	// Windows
	//================================================
	#define NOMINMAX
	#include <Windows.h>
	#include <wrl/client.h>
	#include <cassert>

	//================================================
	// STL
	//================================================
	#include <string>
	#include <filesystem>
}
・リンカーは一番下に書くこと
{
	理 : インクルードとリンカー設定の違いがはっきりして見やすいから
}
4.名前空間について===========================================================================================================================================
・ルート名前空間はFWK、サブ名前空間はアッパーキャメルケース
・ネストされた名前空間構文(namespace FWK::Sub)を使う
{
	例↓
	namespace FWK::Converter
	{
		class AudioManagerJsonConverter final
		{
		};
	}

	使っているサブ名前空間↓
	FWK::Graphics、FWK::Editor、FWK::Physics、FWK::Converter、FWK::Constant、FWK::Struct、FWK::Enum、FWK::Concept、FWK::Utility、FWK::TypeAlias、FWK::TypeTrait
}
・前方宣言は使うクラスの名前空間とは別のブロックで書く
{
	例↓
	namespace FWK
	{
		class AudioManager;
	}

	namespace FWK::Converter
	{
		class AudioManagerJsonConverter final
		{
		};
	}
}
・.cppではnamespaceのブロックを使わずに、関数名をFWK::から全部書く
{
	例↓
	void FWK::Converter::AudioManagerJsonConverter::Deserialize(const nlohmann::json& a_rootJson, AudioManager& a_audioManager) const
	{
		～処理～
	}
}
・using namespaceは使わない
5.変数の命名規則について=====================================================================================================================================
・接頭辞の後ろはロウワーキャメルケース
{
	メンバ変数   m_  例↓ m_masterVolume
	ローカル変数 l_  例↓ l_rootJson
	引数         a_  例↓ a_filePath
	定数         k_  例↓ k_configFileIOPath
	(HLSLのグローバル変数だけ g_ を使う)
}
・構造体のメンバにもm_をつける
{
	例↓
	struct HogeData final
	{
		std::filesystem::path m_filePath = {};
	};
}
・boolはis、has、can、was、shouldから始める
{
	例↓
	bool m_isAudioDeviceResetRequested;
	bool m_wasAudioDeviceReset;
}
・weak_ptrのまま持つローカル変数・ループ変数はWeakを最後につけて、lockしたものと名前を分ける
{
	例↓
	for (const auto& l_soundEffectInstanceWeak : m_soundEffectInstanceList)
	{
		const auto& l_soundEffectInstance = l_soundEffectInstanceWeak.lock();

		if (!l_soundEffectInstance) { continue; }
	}
}
・配列(vectorなど)はList、mapはMapを最後につける
{
	例↓
	std::vector<std::weak_ptr<SoundEffectInstanceBase>> m_soundEffectInstanceList;
	SoundEffectMap                                      m_soundEffectMap;
}
・メンバ名に持ち主のクラス名を繰り返さない
{
	例↓
	StaticModelData::m_meshList ○
	StaticModelData::m_staticModelMeshList ×
}
6.クラス・構造体・Enum・コンセプト・テンプレートの命名について===============================================================================================
・クラス・構造体はアッパーキャメルケース
{
	基底クラスにはBaseをつける                例↓ ComponentBase、EditorWindowBase、SingletonBase
	管理クラスにはManagerをつける             例↓ GraphicsManager、AudioManager
	Json変換クラスにはJsonConverterをつける   例↓ AudioManagerJsonConverter
	エディターに表示するクラスにはInspector   例↓ AssetFilePathInspector
	定数のヘッダーはConstant、構造体はStruct  例↓ AudioManagerConstant.h
	継承したクラスは基底の名前(Baseを除く)をクラス名とファイル名の末尾につける
	                                          例↓ SceneCommandBase → CreateGameObjectSceneCommand(.h/.cpp も同じ名前)
}
・Enumはenum classで定義し、列挙子はアッパーキャメルケース
・無効値が要るEnumは先頭にInvalidを置き、最後の列挙子にもカンマをつける
{
	例↓
	enum class WindowStyle
	{
		Invalid,
		Normal,
		BorderlessFullScreen,
	};

	ビットフラグや大きさを決めたいときだけ型を書く
	enum class AxisBitShiftFlag : std::uint32_t
}
・コンセプトはIs〜Conceptという名前にする
{
	例↓ IsDerivedBaseConcept、IsSmartPTRConcept
}
・テンプレート引数はtypenameを使い、名前はType(複数あるならXxxType)
・requiresは次の行にインデントを1つ下げて書く
{
	例↓
	template <typename Type>
		requires std::is_enum_v<Type>
	class EnumBitShift final
	{
	};
}
・型エイリアスはアッパーキャメルケースで、std::unordered_mapなどの宣言が長くなるものに使う
{
	例↓
	using SoundEffectMap = std::unordered_map<std::filesystem::path, std::shared_ptr<SoundEffect>>;
}
・マクロ名はFWK_をつけ、アッパースネークケースで書く
{
	例↓
	FWK_ASSERT_RETURN_IF
	FWK_DEFINE_TYPE_INFO
	FWK_REGISTER_FACTORY_METHOD
}
7.関数の命名について=========================================================================================================================================
・関数名はアッパーキャメルケース
・ライフサイクル系の関数
{
	初期化処理(InitializeではなくINIT)
	void INIT();

	コンフィグの読み込み・保存
	void LoadCONFIG();
	void SaveCONFIG() const;

	フレームの開始・終了
	void BeginFrame();
	void EndFrame  ();

	更新系
	void EarlyUpdate   ();
	void Update        ();
	void LateUpdate    ();
	void PostLateUpdate();

	作成・解放
	bool Create ();
	void Release();
}
・取得系の関数は「何を返すか」を名前に入れる
{
	REF : 参照を返す
	PTR : ポインタを返す
	VAL : 値を返す
	変更できる参照・ポインタを返すときはMutableをつける

	例↓
	const auto& GetREFAudioEngine        () const { return m_audioEngine; }
	      auto& GetMutableREFAudioEngine ()       { return m_audioEngine; }
	float       GetVALMasterVolume       () const { return m_masterVolume; }

	変数をそのまま返す               : Get
	探して返す(見つからない時がある) : Find
	計算・変換して返す               : Fetch
}
・ゲッターの名前はGet + 種類 + 変数名だけにする(Currentなどの言葉を足した別名のゲッターは作らない)
・セッターはSet + 変数名、引数名はa_set
{
	例↓
	void SetAssetFilePath(const std::filesystem::path& a_set) { m_assetFilePath = a_set; }
}
・値をセットするだけでなく処理もするならApply
{
	例↓
	void ApplyMasterVolume(const float a_volume);
}
・boolを返す判定の関数はIs、Can、Hasから始める
{
	例↓
	bool IsMinimized   () const;
	bool CanLoadFilePath() const;
}
8.変数の書き方について=======================================================================================================================================
・ローカル変数は型を明示する必要がないならautoで書く
{
	型名を書くのはbool、int、floatだけで、それ以外(std::size_t、UINT、DWORD、double、Enum、
	自身のクラス・構造体、外部APIの型など)は右辺で型が決まるならautoにする
	基本はconst auto&、書き換えるならauto&、ポインタはauto*(for文の初期化子・範囲for文も同じ)

	bool、int、float以外でも型名を書くもの↓
	リテラルで初期化する(0ULL、0Uなど型がサフィックスでしか決まらない)
	{}やnullptrで初期化する
	右辺と違う型で受け取る(const char*からstd::stringを作る、std::wstringからstd::filesystem::pathを作るなど)
	ImGuiWindowFlags、ImGuiColなどintの別名(右辺のEnumと型が変わるため)

	例↓
	const auto& l_rootJson = Utility::LoadJsonFile(k_configFileIOPath);

	const auto& l_itemCount = m_itemEnabledList.size();

	const auto l_nextKey = l_isVertical ? ImGuiKey_DownArrow : ImGuiKey_RightArrow;

	auto l_index = m_keySelectedIndex;

	const float l_masterVolume = a_rootJson.value(k_masterVolumeJsonKey, Constant::k_defaultVolume);

	std::size_t l_count = 0ULL;
}
・書き換えないローカル変数にはconstをつける
・8バイト以上のローカル変数は書き換えないなら必ずconst参照で受け取る
{
	すべてのファイルに適用し、コンパイルできないなどの理由がなければ積極的にconst参照を使う
	(if文・switch文の初期化文、範囲for文のループ変数、ラムダの中のローカル変数も同じ)
	理 : コピーを作らずに済み、書き換えないことも型を見ただけで分かるから
	8バイト以上 : クラス、構造体、std::string、std::filesystem::path、std::size_t、std::uint64_t、double、イテレータ、スマートポインタ、
	              boost::uuids::uuid、D3D12_CPU_DESCRIPTOR_HANDLEなど
	8バイト未満(bool、int、float、UINT、DWORD、Enum、DescriptorIndexなど)は参照にせずconst autoで受け取る
	関数の戻り値(一時オブジェクト)をconst参照で受けても、変数の寿命が尽きるまで一時オブジェクトは消えない
	型名を書く変数も同じ(const std::filesystem::path& l_filePath = l_selectedFilePath;)

	参照にしないもの↓
	後から書き換える変数
	元の値が後で変わる・消えるため、取っておく変数(変更前の名前、eraseする要素、popするfront()など)
	std::moveする変数、returnする変数(参照だとmoveできずコピーになる)
	{}で作る変数(参照する元がなく、作った物をそのまま持つため)
	生ポインタ、HANDLE、HWND、HMONITORなど(ポインタは値で持つ)

	例↓
	const auto& l_itemCount = m_itemEnabledList.size();
	const auto& l_label     = std::string{ k_cardPrefixLabel } + a_filePath.generic_string();
	const auto  l_nextKey   = l_isVertical ? ImGuiKey_DownArrow : ImGuiKey_RightArrow;

	// 変更前の名前はSetNameで変わるため、参照にせずコピーを取っておく
	const auto l_beforeName = l_gameObject->GetREFName();

	l_gameObject->SetName(a_newName);
}
・参照で受け取ったローカル変数も書き換えないなら必ずconst参照にする
{
	auto&で受け取っていても、その変数を書き換えない(constの関数を呼ぶ・constの引数に渡すだけ)ならconst auto&にする
	ゲッターもGetMutableREF〜ではなくGetREF〜を使う
	範囲for文のループ変数、if文・switch文の初期化文も同じ
	理 : 書き換えない物を書き換えられる形で持つと、型を見ただけでは書き換えるのか分からないから
	const auto&にしてコンパイルが通らないもの(書き換える関数・参照の引数に渡すもの)だけauto&のままにする

	例↓
	// DrawCopyMenuなどはconst AssetBrowserEditorWindowFileOperation&で受け取るため、書き換えない
	const auto& l_fileOperation = a_editorWindow.GetREFFileOperation      ();
	      auto& l_clipboard     = a_editorWindow.GetMutableREFClipboard   ();
}
・クラスや構造体の初期化には波括弧初期化を使う
{
	例↓
	nlohmann::json l_rootJson = {};
}
・ポインタの場合は明示的にnullptrを代入する
{
	例↓
	Hoge* l_hoge = nullptr;
}
・&と*は型にくっつけて書く
{
	例↓
	const auto& l_hoge = ...;
	Hoge*       l_hoge = nullptr;
}
・変数の宣言が続くときは行間を開けずに、型と名前と=の位置を揃える
・const修飾子と型の位置を合わせない
{
	もしconst修飾子を持つ変数とそうでない変数を行間なしにくっつけて書く場合
	型の位置をconstに合わせるのではなくconstの後ろに続く型に合わせる
	理 : そうしたほうがconstなのかそうでないかが一目でわかるから

	例↓
	      auto& l_inputManager       = FWK::InputManager::GetInstance         ();
	const auto& l_keyboardController = l_inputManager.GetREFKeyboardController();
}
・関数の呼び出しが続くときは()の位置を揃える
{
	理 : ()の位置が揃うことで関数呼び出しの境界が一目で分かるから
	基本ルール : 関数名が長い方の()の位置に合わせる
	上下に隣接する行はif文以外すべて揃える(1文字でもずれていたら直す)
	変数の宣言(const auto& / auto& / 代入)の右辺の呼び出しも同じ
	ゲッターの名前が変わって長さが変わったときも、隣接する行の()の位置を揃え直す
	1引数1行で改行した関数は揃えずに1行開ける(11章「1引数1行で改行した関数は〜」)

	例↓
	auto& l_physicsManager  = FWK::Physics::PhysicsManager::GetInstance  ();
	auto& l_graphicsManager = FWK::Graphics::GraphicsManager::GetInstance();
	auto& l_audioManager    = FWK::AudioManager::GetInstance             ();

	l_graphicsManager.INIT();
	l_physicsManager.INIT ();
	l_audioManager.INIT   ();
}
・引数の数が同じ呼び出しが続くなら、2つ目以降の引数の位置も揃える
{
	例↓
	FWK_ASSERT_RETURN_VALUE_IF(!CreateCommandQueue(a_device), "コマンドキューの作成に失敗しました。", false);
	FWK_ASSERT_RETURN_VALUE_IF(!CreateFence(a_device),       "フェンスの作成に失敗しました。",         false);
}
・論理演算子(&&、||)を使う場合は演算子ごとに改行し、演算子は行末に書く(EditorPopupNavigator::ApplyItemStateの書き方)
{
	2つ目以降の項は1つ目の項の先頭に揃える(()の中の項は(の次の文字に揃える)
	演算子の位置は、()の中も含めた式全体で演算子のある一番長い行に揃える(演算子のない最後の行は含めない)
	項が2つだけでも、短くても1行に書かない
	returnかcontinueだけのif文でも、論理演算子があるならブロックにする
	関数の引数の中で改行したら、その関数の引数はすべて1引数1行にする
	論理演算子を使った変数の宣言は、隣の変数の宣言と関係があっても必ず1行開ける(=の位置は揃えたままでよい)
	理 : 演算子が縦に並ぶことで条件の数と、&&と||のどちらでつないでいるかが一目で分かるから
	     変数ごとに行間があることで、どこまでが1つの変数の条件なのかが一目で分かるから

	例↓
	// × (どちらも関数の引数に渡す変数)
	const bool l_canRename    = !l_isMultiSelection &&
	                            !l_isRootFolder;
	const bool l_canDuplicate = l_hasSelection &&
	                            !l_containsRoot;

	// ○
	const bool l_canRename    = !l_isMultiSelection &&
	                            !l_isRootFolder;

	const bool l_canDuplicate = l_hasSelection &&
	                            !l_containsRoot;

	例↓
	const bool l_isHovered = a_isEnabled &&
	                         ImGui::IsItemHovered();

	if (l_isHovered ||
	    l_isKeySelected)
	{
		DrawItemFrame();
	}

	return a_isClicked      ||
	       (l_isKeySelected &&
	        a_isEnabled     &&
	        m_isConfirmRequested);

	// ×
	if (!m_uploadBuffer || !m_mappedData) { return; }

	// ○
	if (!m_uploadBuffer ||
	    !m_mappedData)
	{
		return;
	}
}
・ビット演算子を使う場合
{
	3つ以下なら改行しない
	4つ以上なら改行して縦に並べる
	理 : 演算子が縦に並ぶことでフラグの数と内容が一目で分かるから

	例↓
	const int l_flags = flagA |
	                    flagB |
	                    flagC |
	                    flagD;
}
・符号の位置は合わせる
{
	理 : 正の数か負の数かが瞬時にわかりやすいため
	※符号なしの数値は符号分のスペースを空けておく

	例↓
	static constexpr float k_soundEffectInstance2DMINPan = -1.0F;
	static constexpr float k_soundEffectInstance2DMAXPan =  1.0F;
}
・{}の初期化子は要素が4つ以上なら縦に並べ、3つ以下なら1行で書く
{
	例↓
	static constexpr TypeAlias::Math::Color k_defaultColor =
	{
		1.0F,
		1.0F,
		1.0F,
		1.0F
	};

	ImVec2 l_size = { 0.0F, 240.0F };
}
・数学の型はTypeAlias::Math::を使う
{
	例↓
	TypeAlias::Math::Vector3
	TypeAlias::Math::Matrix
}
9.数値リテラルについて=======================================================================================================================================
・floatには大文字のFをつけ、小数点以下を必ず書く
{
	例↓
	1.0F
	0.5F
}
・std::size_tやstd::uint64_tにはULL、std::uint32_tやUINTにはUをつける
{
	例↓
	static constexpr std::size_t k_initialIndex = 0ULL;
	static constexpr UINT        k_bufferCount  = 2U;
}
・数値は直接書かずに定数にする(マジックナンバーを書かない)
{
	数値をそのまま書いてよいのは定数の定義とfor文の初期化子だけ
	if文・while文の条件、計算(+1、-1、%など)、変数やメンバの初期化に書く0や1もマジックナンバーとして定数にする
	理 : 0や1でも「何の0なのか」「なぜ1つずらすのか」が名前で分かるようにするため

	例↓
	// ×
	if (l_itemCount == 0ULL) { return; }

	l_index = (l_index + 1ULL) % l_itemCount;

	// ○
	static constexpr std::size_t k_emptyItemCount   = 0ULL;
	static constexpr std::size_t k_keySelectionStep = 1ULL;

	if (l_itemCount == k_emptyItemCount) { return; }

	l_index = (l_index + k_keySelectionStep) % l_itemCount;

	// for文の初期化子だけはそのまま書いてよい
	for (std::size_t l_index = 0ULL; l_index < l_count; ++l_index)
	{
	}
}
・値に意味がないもの(パディングなど)は数値を書かずに{}で初期化する
{
	例↓
	float m_padding = {};
}
10.関数の引数について=========================================================================================================================================
・書き換えない引数にはconstをつける(値渡しの組み込み型も)
{
	例↓
	void ApplyMasterVolume(const float a_volume);
}
・8バイト以上のもの(クラス、構造体、std::string、std::size_t、std::uint64_t、doubleなど)はすべてconst参照で渡す(書き換えるなら参照)
{
	8バイト未満(bool、int、float、UINT、Enumなど)と生ポインタ・HANDLEはconstの値で渡す
	外部APIが決めた形の関数(WNDPROC、ImGuiのコールバック、overrideなど)は変えない

	例↓
	void ResizeBackBufferList(const std::size_t& a_backBufferNUM);
}
・スマートポインタ
{
	基本はconst std::weak_ptr<T>&
	所有を共有して保持する引数だけconst std::shared_ptr<T>&

	例↓
	void AddEffectInstance(const std::weak_ptr<SoundEffectInstanceBase>& a_soundEffectInstanceBase);
}
・文字列はconst std::string&、ファイルパスはconst std::filesystem::path&
・引数の並びは変数の書き順(13章)と同じにする
{
	constの引数を先にまとめ、その後ろにconstでない引数を書く
	const 配列 → const 参照 → const ポインタ → const 値 → 配列 → 参照 → ポインタ → 値

	配列は渡し方に関係なく型で見る(const std::vector<T>&は配列)
	スマートポインタは渡し方で見る(const std::weak_ptr<T>&は参照、値で渡すなら値ではなくポインタ)
	参照と値の中は13章の型の順(class → classのTypeAlias → 構造体 → 構造体のTypeAlias → Enum → EnumのTypeAlias → char → double → float → unsigned long long → unsigned long → unsigned int → int → bool)
	同じ順位の引数は意味の流れ(元 → 先、前 → 後など)で並べる

	例↓
	// ×
	void DrawGameObjectDropZone(const std::weak_ptr<GameObject>& a_targetGameObject, Scene& a_scene, const bool a_isDropAfter);

	// ○
	void DrawGameObjectDropZone(const std::weak_ptr<GameObject>& a_targetGameObject, const bool a_isDropAfter, Scene& a_scene);
}
・デフォルト引数があるときは、デフォルト引数でない引数とデフォルト引数をそれぞれ別に上の順番で並べ、デフォルト引数は後ろにまとめる
{
	例↓
	bool MenuItem(const char* a_label, const char* a_shortcut = nullptr, const bool a_isEnabled = true);
}
・外部APIが決めた引数(オーバーライド、コールバック)と可変長引数(Args&&...)は並べ替えない
11.関数の宣言について=========================================================================================================================================
・隣接する関数で戻り値の後にスペーシングを挟んで関数名を書く場合は一番長い戻り値型に合わせる
{
	理 : 戻り値型と関数名の区切りが揃うことで可読性が高まるから
	※隣接する関数同士にのみ適用し、離している関数には適用しない

	例↓
	std::weak_ptr<SoundEffect> AddSoundEffect   (const std::filesystem::path&                  a_filePath);
	void                       AddEffectInstance(const std::weak_ptr<SoundEffectInstanceBase>& a_soundEffectInstanceBase);
}
・隣接する関数は()の位置、引数の型・名前、末尾のconstの位置を揃える
{
	例↓
	void StopAllSound  () const;
	void PauseAllSound () const;
	void ResumeAllSound() const;
}
・似た処理の関数は行間を開けずに並べ、違う処理なら1行開ける
・処理フローの両端に位置する関数は似ていても離す
{
	例↓
	void Deserialize(const nlohmann::json& a_rootJson);

	nlohmann::json Serialize() const;
}
・関数の引数が4個以上なら1引数1行で改行する(3個以下なら長くても改行しない)
{
	宣言・定義・呼び出しのすべてに適用する(コンストラクタ、テンプレート関数、マクロ、外部APIの呼び出しも含む)
	if文の()の中に書く関数も同じで、3個以下は改行しない(16章「if文の()の中に書く関数は〜」)
	1つ目の引数は ( と同じ行に書き、2つ目以降は1つ目の引数の先頭に揃える
	宣言・定義では型と引数名の列も揃える
	理 : 引数の数と並びが縦に一目で分かり、引数を足す・消すときの差分が1行で済むから

	例↓
	// 宣言
	void RequestSpriteDraw(const Math::Vector2&      a_pos,
	                       const Math::Vector2&      a_scale,
	                       const Texture&            a_texture,
	                       const Struct::SpriteRect* a_sourceRect);

	// 呼び出し
	// ×
	SelectGameObject(l_next, a_isRangeSelection, false, *l_scene);

	// ○
	SelectGameObject(l_next,
	                 a_isRangeSelection,
	                 false,
	                 *l_scene);

	// 入れ子の呼び出しも内側の(に揃える
	ImGui::PushStyleColor(ImGuiCol_Text,
	                      IM_COL32(l_color.x,
	                               l_color.y,
	                               l_color.z,
	                               l_color.w));
}
・1引数1行で改行した関数は、続く関数と()の位置を揃えずに1行開けて書く(すべてのファイルに適用)
{
	()の位置を揃える(上の「関数の呼び出しが続くときは()の位置を揃える」)のは1行で書いた関数どうしだけにする
	宣言・定義・呼び出しのすべてに適用する
	ただし.cppの関数定義どうしは、似た処理なら1行開けずにくっつける(15章「.hで1引数1行に改行したために〜」)
	参考 : AssetBrowserEditorWindowPopupDrawer.h / .cpp の DrawCopyMenu 〜 DrawDeleteMenu
	理 : 改行した関数は縦に長く、()の位置を揃えても境界は分からず、関数名と(の間の空白で引数の列が右へずれるだけだから

	例↓
	// ×
	DrawDuplicateMenu(a_selectedFilePathList,
	                  l_fileOperation,
	                  l_hasSelection &&
	                  !l_containsRoot);
	DrawDeleteMenu   (a_selectedFilePathList,
	                  l_hasSelection &&
	                  !l_containsRoot,
	                  a_editorWindow);

	// ○
	DrawDuplicateMenu(a_selectedFilePathList,
	                  l_fileOperation,
	                  l_hasSelection &&
	                  !l_containsRoot);

	DrawDeleteMenu(a_selectedFilePathList,
	               l_hasSelection &&
	               !l_containsRoot,
	               a_editorWindow);

	// 1行で書いた関数は今まで通り()の位置を揃える
	void DrawDuplicateMenu(const std::vector<std::filesystem::path>& a_selectedFilePathList, const AssetBrowserEditorWindowFileOperation& a_fileOperation, const bool               a_hasSelection);
	void DrawDeleteMenu   (const std::vector<std::filesystem::path>& a_selectedFilePathList, const bool                                   a_hasSelection, AssetBrowserEditorWindow& a_editorWindow);
}
・関数の書く順番
{
	大まかな処理順を優先
	void INIT      ();
	void LoadCONFIG();
	void Update    ();
	void SaveCONFIG() const;

	処理関数 → Is/Can/Has → Apply → Set → Fetch/Find → GetREF → GetMutableREF → GetPTR → GetMutablePTR → GetVAL
	.cppの定義もヘッダーと同じ順番で書く
}
・ゲッター・セッター・1行で済む処理はヘッダーに書き、ゲッターの戻り値はautoにする
{
	例↓
	const auto& GetREFAudioEngine() const { return m_audioEngine; }

	組み込み型を値で返す場合は型名を書く
	float GetVALMasterVolume() const { return m_masterVolume; }
}
12.クラスについて=============================================================================================================================================
・継承させないクラス・構造体には必ずfinalをつける
・クラスの書き方
{
	class Hoge final
	{
	private:

		そのクラスでしか使わない構造体、Enum、型エイリアスはprivateの一番上に書く
		using HogeStringMap = std::unordered_map<std::string, std::string>;

	public:

		 Hoge() = default;
		~Hoge() = default;

		公開する関数(関数の書く順番を参照)

	private:

		privateの関数

		マクロ(アクセス指定子を変える可能性があるので一番下)
	};

	アクセス指定子の次の行は必ず1行開ける
}
・コンストラクタとデストラクタはクラス名の位置を揃える
{
	理 : ~の位置が分かりやすくなり一瞬でコンストラクタ・デストラクタを見分けることができるから

	例↓
	 Hoge() = default;
	~Hoge() = default;

	基底クラス
	         HogeBase() = default;
	virtual ~HogeBase() = default;

	派生クラス
	 Hoge()          = default;
	~Hoge() override = default;
}
・メンバの初期化は2種類のどちらかにそろえる(混ぜない)
{
	理 : どちらで初期化されているかが一目で分かり、二重初期化にならないから

	コンストラクタが= defaultのとき : メンバの宣言で初期化する
	int m_a = 0;

	コンストラクタを.cppに書くとき : 全メンバを初期化子リストで初期化し、宣言には何も書かない
	int m_a;
}
・派生クラスの仮想関数にはoverrideをつける(virtualは書かない)
・コピーを禁止するときは4つまとめて書く
{
	例↓
	Hoge(const Hoge&)           = delete;
	Hoge(      Hoge&&) noexcept = default;

	Hoge& operator=(const Hoge&)           = delete;
	Hoge& operator=(      Hoge&&) noexcept = default;
}
・シングルトンのクラス

		friend class SingletonBase<Hoge>;

	public:
		...
	};

}

13.メンバ変数・定数の並び順について===========================================================================================================================
・メンバ変数・定数はまず修飾子で分け、次の順に書く
{
	inline static constexpr(名前空間ではinline constexpr)
	static constexpr
	inline static const(名前空間ではinline const)
	static const
	static
	const
	修飾子なし
}
・同じ修飾子の中は配列 → 参照 → ポインタ → 値の順に書く
{
	配列     : std::vector、std::array、std::unordered_map、ImVectorなど(配列のTypeAliasも配列)
	参照     : Hoge&
	ポインタ : std::unique_ptr、std::shared_ptr、std::weak_ptr、ComPtr、Hoge*、HWNDなど
	値       : それ以外
}
・値の中は型で次の順に書く
{
	class(外部API → std → 自身作成)
	classのTypeAlias(外部API → std → 自身作成)
	構造体(外部API → std → 自身作成)
	構造体のTypeAlias(外部API → std → 自身作成)
	Enum(外部API → std → 自身作成)
	EnumのTypeAlias(外部API → std → 自身作成)
	char
	double
	float
	unsigned long long(std::size_t、std::uint64_t、UINT64)
	unsigned long(DWORD)
	unsigned int(UINT、std::uint32_t、TypeAlias::DescriptorIndexなど)
	int
	bool

	std::string、std::filesystem::path、std::function、std::mutexはstdのclass
	nlohmann::jsonは外部APIのclass、boost::uuids::uuid、ImVec2、D3D12_～は外部APIの構造体
	TypeAlias::Math::Vector3などは外部API構造体のTypeAlias
	数値のTypeAlias(TypeAlias::DescriptorIndexなど)は元の数値の型で並べる
	同じ順位のものは今の順番のまま並べる

	static constexpr float k_itemFrameThickness = 2.0F;

	前の定数を使って作る定数(配列の要素数など)は使われる定数を先に書く
	理 : 並びを変えると見た目は同じでもメモリの並び・破棄の順番が変わり、動かなくなるから
}

16.ブレースとif文について=====================================================================================================================================
・関数・クラス・制御文の開きブレースは改行して次の行に書く
{
	例↓
	if (m_isAudioDeviceResetRequested)
	{
		m_isAudioDeviceResetRequested = false;
	}
}
・if、for、while、switchの後ろは1つ空白を開ける
・処理がreturnかcontinueだけのときは1行で書く(breakや他の処理はブロックにする)
{
	例↓
	if (!m_audioEngine) { return; }

	if (!l_soundEffectInstance) { continue; }
}
・連続してif文を書く、それがreturn文の場合()の位置を揃える
{
	例↓
	if      (m_isA)  { return false; }
	else if (m_isAB) { return false; }
}
・論理演算子をif文で使うときも8章と同じく改行し、演算子の位置を揃える(!の分はずらさない)
{
	例↓
	if (!m_audioEngine->Update()         &&
	    m_audioEngine->IsCriticalError() &&
	    m_isAudioDeviceResetRequested)
	{
		...
	}
}
・if文の()の中に書く関数は、引数が3個以下なら改行せず1行で書き、改行してよいのは引数4個以上のときだけ(すべてのファイルに適用)
{
	引数4個以上なら11章の通り1引数1行で改行する
	else if、if文の初期化文に書く関数も同じ
	論理演算子の改行(上の決まり)は今まで通りで、引数が3個以下の関数の中では改行しない
	1行に書けないもの(ラムダを渡す呼び出し)だけは改行する
	理 : 引数が少ない関数まで縦に並ぶと、条件がいくつあり、どこで終わるのかが分かりにくくなるから

	例↓
	// ×
	if (m_popupNavigator.MenuItem(l_label.c_str(),
	                              k_copyShortcutLabel.data(),
	                              a_hasSelection))
	{
		...
	}

	if (!std::filesystem::is_directory(l_initialDirectoryPath,
	                                   l_errorCode) ||
	    l_errorCode)
	{
		return false;
	}

	// ○
	if (m_popupNavigator.MenuItem(l_label.c_str(), k_copyShortcutLabel.data(), a_hasSelection))
	{
		...
	}

	if (!std::filesystem::is_directory(l_initialDirectoryPath, l_errorCode) ||
	    l_errorCode)
	{
		return false;
	}

	// 引数4個以上は今まで通り1引数1行
	if (Utility::IsSameSize(m_width,
	                        m_height,
	                        a_width,
	                        a_height))
	{
		return true;
	}
}
・if文でしか使わない変数(if文の条件と中でしか使わない変数)は、if文の外で宣言せずif文の中に書く
{
	理 : 値が判定の直前に作られるため、宣言から判定までの間に値が古くなったり、別の場所で使われたりすることがなく判定が確実になるから
	条件で1回しか使わないbool(Is・Has・Can・Shouldで始まる名前をautoで受けたものも含む)は変数を作らず、式を条件へ直接書く
	　名前を付けないと意味が分からない長い式でも変数にしない(意味はif文の上のコメントに書く)
	　式に論理演算子があれば8章と同じく改行して演算子の位置を揃える
	それ以外(条件と中の両方で使う、bool以外)はif文の初期化文で宣言する
	　初期化文の後の条件は改行し、「if (」の次の文字に揃える
	　returnかcontinueだけの1行のif文でも、初期化文を書くならブロックにする
	次の変数はif文の外で宣言してよい
	　2つ以上のif文や、if文の外でも使う変数
	　宣言からif文までの間に値や状態を変える処理がある変数(ImGuiの描画、保存、通知の登録など。中へ移すと処理の順番が変わり結果が変わる)
	　初期化文はif文1つに1つしか書けないため、同じif文で使う変数が2つ以上あるときは、条件に一番近い1つだけを初期化文に入れ残りは外で宣言する
	　constexprの定数

	例↓
	// ×
	const bool l_isRangeSelection = l_io.KeyShift || l_io.KeyCtrl;

	if (l_isRangeSelection)
	{
		...
	}

	const auto& l_itr = m_soundEffectMap.find(a_filePath);

	if (l_itr != m_soundEffectMap.end())
	{
		return l_itr->second;
	}

	const auto& l_beforePass = a_passList[l_beforePassIndex];

	if (!l_beforePass) { continue; }

	// ○
	if (l_io.KeyShift ||
	    l_io.KeyCtrl)
	{
		...
	}

	if (const auto& l_itr = m_soundEffectMap.find(a_filePath);
	    l_itr != m_soundEffectMap.end())
	{
		return l_itr->second;
	}

	if (const auto& l_beforePass = a_passList[l_beforePassIndex];
	    !l_beforePass)
	{
		continue;
	}

	// ○ 間に描画があるので外で宣言したままにする
	const bool l_isEnterPressed = ImGui::InputText(...);

	ImGui::PopStyleVar();

	if (l_isEnterPressed)
	{
		...
	}
}

	if (!m_audioEngine) { return {}; }
}
19.コメントについて===========================================================================================================================================
・コメントは//を使い、//の後ろに空白を1つ開ける(/* */は使わない)
・コメントは日本語で書き、最後に「。」はつけない
・長くなるときは「、」で区切って次の行に続ける
{
	例↓
	// AudioEngine生成前にVolumeだけを設定された場合でも、
	// m_masterVolumeには値を保持しておく
}
・コメントは処理の上の行に書く(行の後ろには書かない)
・クラスの宣言(ヘッダー)には説明のコメントを書かない、処理の中身にコメントを書く
{
	理 : 宣言は名前で分かるようにして、なぜその処理をするのかは処理の近くに書いたほうが読みやすいから
	※ヘッダーに処理を書くUtilityやテンプレートは処理の中にコメントを書く
}
・何をするかだけでなく、なぜそうするのかを書く
{
	例↓
	// ヘッドホンやスピーカーの抜き差しなどによって
	// AudioEngineのReset要求が出ている場合、一度だけResetを試す
}
20.エラー処理について=========================================================================================================================================
・失敗したら処理を抜けるところはFWK_ASSERT_RETURN_IF / FWK_ASSERT_RETURN_VALUE_IFを使う
・メッセージは日本語で書き、最後に「。」をつける
{
	例↓
	FWK_ASSERT_RETURN_IF(!l_fence, "フェンスが作成されていません。");

	FWK_ASSERT_RETURN_VALUE_IF(!m_commandQueue, "コマンドキューが作成されていません。", false);
}
・HRESULTはFAILED()で判定する
{
	例↓
	if (FAILED(l_result)) { return false; }
}
21.定数について===============================================================================================================================================
・クラススコープの定数はstatic constexpr
・名前空間スコープの定数はinline constexpr
・ファイルパスなどconstexprにできないものはinline static const(名前空間スコープはinline const)
{
	例↓
	static constexpr float k_minMasterVolume = 0.0F;

	namespace FWK::Constant
	{
		inline constexpr float k_defaultVolume = 1.0F;
	}

	inline static const std::filesystem::path k_configFileIOPath = "CONFIG/Audio/AudioCONFIG.json";
}
・そのクラスでしか使わない定数はクラスのprivateに、複数のクラスで使う定数はDefinition/Constantに書く
・クラス・構造体のpublicに定数を書かない(入れ子の構造体の中も同じ)
{
	外から使う定数・構造体の初期値はDefinition/Constant/<機能>/<クラス名>Constant.hのnamespace FWK::Constantに書き、Constant::で使う
	VisualStudioのConstantフィルターに登録し、Framework.hではそのクラスより前に読み込む
	理 : publicに書くとHoge::k_〜、派生クラス::k_〜など呼び方がばらばらになり、どこで定義したか探しにくくなるから

	例↓
	namespace FWK::Constant
	{
		inline constexpr UINT64 k_unusedFenceValue = 0ULL;
	}

	if (a_fenceValue == Constant::k_unusedFenceValue) { return true; }
}
・Constantの中は全部同じ名前空間になるので、ぶつかる名前には持ち主の名前を入れる
{
	例↓
	k_initialAssetBrowserRenameIsActive、k_initialWorldOutlinerRenameIsActive
	同じ意味・同じ値の定数は1つにまとめる(Fence、CommandAllocatorのk_unusedFenceValueなど)
}
・列挙子の値のためだけの定数は作らない

	const auto& l_gameObject = a_gameObject.lock();

}

24.使わないもの===============================================================================================================================================
・this->
・Cスタイルのキャスト(static_castを使う)
・RTTI(dynamic_cast / std::dynamic_pointer_cast / typeid / std::type_info / std::type_index / std::any)(TypeINFOのStaticTypeIDで判定する)
{
	理 : dynamic_castは実行時にRTTIの継承表を探すため重い。TypeINFOなら親の数だけ番号を比較するだけで済む

	例外 : EditorManager(エディター)で使うstd::anyだけはよい(IMGUIDragDropPayloadStorageのドラッグ&ドロップのPayload)
	       エディター以外(ゲーム・描画・物理など)では使わない

	基底クラスにFWK_DEFINE_TYPE_INFO_ROOT、派生クラスにFWK_DEFINE_TYPE_INFOを書き、
	継承しているかはUtility::IsDerivedTypeINFOで調べ、継承していればstatic_cast / std::static_pointer_castで戻す

	例↓
	if (!Utility::IsDerivedTypeINFO(a_command.GetREFRuntimeTypeINFO(), SceneCommandBase::GetREFTypeINFO())) { return; }

	const auto& l_sceneCommand = static_cast<const SceneCommandBase&>(a_command);

	同じ型かだけを調べるならk_staticTypeIDを直接比較する
	if (a_component.GetREFRuntimeTypeINFO().k_staticTypeID == TransformComponent::GetREFTypeINFO().k_staticTypeID) { ... }
}
・関数ポインタ・メンバ関数ポインタ(using Hoge = bool (Class::*)(...); / &Class::Func を値として渡す / std::invoke)
{
	理 : どの関数が呼ばれるかが呼び出し側を見ないと分からず読みにくい。nullptrの確認も要る

	種類ごとに呼ぶ関数を変えるときは、種類のEnumをテンプレート引数で受け取りif constexprで呼び分ける
	使えない種類はstatic_assertでコンパイルエラーにする
	種類が実行中にしか分からないとき(Jsonから読んだ値など)だけ、Enumを引数で受け取りswitchで呼び分ける
	クラスごとに違う処理なら継承の仮想関数にする

	例↓
	template <Enum::AssetFilePathRegistryType RegistryType>
	bool WriteNewAssetFile(const std::filesystem::path& a_filePath, const boost::uuids::uuid& a_uuid) const
	{
		static_assert(RegistryType == Enum::AssetFilePathRegistryType::Prefab ||
		              RegistryType == Enum::AssetFilePathRegistryType::Scene,
		              "書き込み方が決まっていないアセットの種類です");

		if constexpr (RegistryType == Enum::AssetFilePathRegistryType::Prefab)
		{
			return WriteNewPrefabFile(a_filePath, a_uuid);
		}
		else
		{
			return WriteNewSceneFile(a_filePath);
		}
	}

	呼び出し↓
	WriteNewAssetFile<Enum::AssetFilePathRegistryType::Prefab>(l_filePath, l_uuid);
}
・NULL(nullptrを使う)
・using namespace
・[[nodiscard]]
・noexcept(ムーブのdefaultだけ)
・ラムダ(std::ranges::any_ofなどの条件にだけ使う、それ以外は関数にする)
・自作の関数の戻り値に続けて関数を呼ぶこと(lock()だけはよい)
{
	例↓
	const auto& l_hierarchy = l_gameObject->GetREFHierarchy();
	const auto& l_parent    = l_hierarchy.GetREFParent().lock();
}
25.HLSLについて===============================================================================================================================================
・ファイル名の最後にシェーダーの種類をつける
{
	_VS : 頂点シェーダー
	_PS : ピクセルシェーダー
	_MS : メッシュシェーダー
	_AS : 増幅シェーダー
	_CS : コンピュートシェーダー
	共通の処理は.hlsliに書く
}
・.hlsliはインクルードガードを書く
{
	例↓
	#ifndef FINAL_COLOR_HLSLI
	#define FINAL_COLOR_HLSLI
	#include "../FullScreenTriangle.hlsli"

	～処理～

	#endif // FINAL_COLOR_HLSLI
}
・エントリーポイントはmain
・cbufferの名前はCB〜、中の変数とテクスチャ・サンプラーはg_
・16バイトにそろえるための変数はg_padding
{
	例↓
	cbuffer CBFinalColorPass : register(b0)
	{
		uint   g_sceneColorTextureSRVIndex;
		float3 g_padding;
	}

	SamplerState g_sceneColorSampler : register(s0);
}
・定数はstatic const、名前はk_、floatにはFをつける
{
	例↓
	static const float k_finalColorGammaBase = 2.2F;
}
・ローカル変数はl_、引数はa_で、書き換えない引数にもconstをつける
・C++と同じく宣言が続くときは型と名前と=を揃える
{
	例↓
	const float3 l_outputColorRGB = ConvertLinearColorToSimpleSRGB(l_linearColor.rgb);
	const float  l_outputAlpha    = ConvertFinalColorAlpha        (l_linearColor.a);
}
・テクスチャはResourceDescriptorHeap[添字]で取り出す
