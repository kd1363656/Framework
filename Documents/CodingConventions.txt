1.ファイルについて===========================================================================================================================================
・ファイル名はアッパーキャメルケースで書き、クラス名と同じにする(.hと.cppは同じ名前)
{
	例↓
	AudioManager.h
	AudioManager.cpp
}
・文字コードはBOM付きUTF-8、改行コードはCRLF
・インデントはスペース4つ(タブは使わない)
・ファイルの最終行に改行を入れない
{
	理 : 不要な空行ができるのを防ぐため
	例↓
	class Hoge final
	{
		～処理～
	};
	←改行なしで終わる
}
・ヘッダーの1行目は必ず#pragma once
・空行は2行以上続けない
・行末に空白を残さない
・置き場所
{
	クラス                   : そのクラスの機能のフォルダ(Audio/、Graphics/Command/Queue/ など)
	Jsonの変換クラス         : 変換したいクラスのフォルダ/Converter/Json/
	定数                     : Definition/Constant/<機能>/<クラス名>Constant.h
	構造体                   : Definition/Struct/<機能>/<クラス名>Struct.h
	Enum                     : Definition/Enum/<機能>/
	コンセプト               : Definition/Concept/
	マクロ                   : Definition/Macros/
	型エイリアス・型トレイト : Definition/Type/Alias/、Definition/Type/Trait/
	共通処理                 : Utility/<機能>/<名前>Utility.h

	1ファイルだけのために下位フォルダは作らない
}
2.省略形の名前について=======================================================================================================================================
・省略形の名前を書く際はすべて大文字にする(jsonのキー文字には適用しない)
{
	アッパーキャメルケースの場合
	PCH
	WindowCONFIG;

	ロウワーキャメルケースの場合
	pch
	windowCONFIG;

	よく使うもの↓
	INIT、CONFIG、REF、PTR、VAL、UUID、INFO(TypeINFO)、MIN、MAX、NUM、FPS、IMGUI、SRV、UAV、CB、VB、IB、GPU、CPU、FBX
}
3.インクルードについて=======================================================================================================================================
・.cppの1行目は自分のヘッダーのインクルードだけを書く
{
	理 : 他のヘッダーはPCH.hとFramework.hにまとめてあるので.cppで個別にインクルードする必要がないから

	例↓
	#include "AudioManager.h"

	FWK::AudioManager::AudioManager() :
	...
}
・新しくヘッダーを作ったらFramework.hにインクルードを追加する
・プリコンパイル済みヘッダーではインクルードしたものが関係の深いものなら隣接して#include文を書き
そうでなければ1行、行間を開けて書く
コメントでインクルードしているものについて書く
{
	理 : 何をインクルードしているのか分かりやすいようにするため、
	コメントは索引として書く

	例↓
	//================================================
	// Windows
	//================================================
	#define NOMINMAX
	#include <Windows.h>
	#include <wrl/client.h>
	#include <cassert>

	//================================================
	// STL
	//================================================
	#include <string>
	#include <filesystem>
}
・リンカーは一番下に書くこと
{
	理 : インクルードとリンカー設定の違いがはっきりして見やすいから
}
4.名前空間について===========================================================================================================================================
・ルート名前空間はFWK、サブ名前空間はアッパーキャメルケース
・ネストされた名前空間構文(namespace FWK::Sub)を使う
{
	例↓
	namespace FWK::Converter
	{
		class AudioManagerJsonConverter final
		{
		};
	}

	使っているサブ名前空間↓
	FWK::Graphics、FWK::Editor、FWK::Physics、FWK::Converter、FWK::Constant、FWK::Struct、FWK::Enum、FWK::Concept、FWK::Utility、FWK::TypeAlias、FWK::TypeTrait
}
・前方宣言は使うクラスの名前空間とは別のブロックで書く
{
	例↓
	namespace FWK
	{
		class AudioManager;
	}

	namespace FWK::Converter
	{
		class AudioManagerJsonConverter final
		{
		};
	}
}
・.cppではnamespaceのブロックを使わずに、関数名をFWK::から全部書く
{
	例↓
	void FWK::Converter::AudioManagerJsonConverter::Deserialize(const nlohmann::json& a_rootJson, AudioManager& a_audioManager) const
	{
		～処理～
	}
}
・using namespaceは使わない
5.変数の命名規則について=====================================================================================================================================
・接頭辞の後ろはロウワーキャメルケース
{
	メンバ変数   m_  例↓ m_masterVolume
	ローカル変数 l_  例↓ l_rootJson
	引数         a_  例↓ a_filePath
	定数         k_  例↓ k_configFileIOPath
	(HLSLのグローバル変数だけ g_ を使う)
}
・構造体のメンバにもm_をつける
{
	例↓
	struct HogeData final
	{
		std::filesystem::path m_filePath = {};
	};
}
・boolはis、has、can、was、shouldから始める
{
	例↓
	bool m_isAudioDeviceResetRequested;
	bool m_wasAudioDeviceReset;
}
・weak_ptrのまま持つローカル変数・ループ変数はWeakを最後につけて、lockしたものと名前を分ける
{
	例↓
	for (const auto& l_soundEffectInstanceWeak : m_soundEffectInstanceList)
	{
		const auto& l_soundEffectInstance = l_soundEffectInstanceWeak.lock();

		if (!l_soundEffectInstance) { continue; }
	}
}
・配列(vectorなど)はList、mapはMapを最後につける
{
	例↓
	std::vector<std::weak_ptr<SoundEffectInstanceBase>> m_soundEffectInstanceList;
	SoundEffectMap                                      m_soundEffectMap;
}
・メンバ名に持ち主のクラス名を繰り返さない
{
	例↓
	StaticModelData::m_meshList ○
	StaticModelData::m_staticModelMeshList ×
}
6.クラス・構造体・Enum・コンセプト・テンプレートの命名について===============================================================================================
・クラス・構造体はアッパーキャメルケース
{
	基底クラスにはBaseをつける                例↓ ComponentBase、EditorWindowBase、SingletonBase
	管理クラスにはManagerをつける             例↓ GraphicsManager、AudioManager
	Json変換クラスにはJsonConverterをつける   例↓ AudioManagerJsonConverter
	エディターに表示するクラスにはInspector   例↓ AssetFilePathInspector
	定数のヘッダーはConstant、構造体はStruct  例↓ AudioManagerConstant.h
}
・Enumはenum classで定義し、列挙子はアッパーキャメルケース
・無効値が要るEnumは先頭にInvalidを置き、最後の列挙子にもカンマをつける
{
	例↓
	enum class WindowStyle
	{
		Invalid,
		Normal,
		BorderlessFullScreen,
	};

	ビットフラグや大きさを決めたいときだけ型を書く
	enum class AxisBitShiftFlag : std::uint32_t
}
・コンセプトはIs〜Conceptという名前にする
{
	例↓ IsDerivedBaseConcept、IsSmartPTRConcept
}
・テンプレート引数はtypenameを使い、名前はType(複数あるならXxxType)
・requiresは次の行にインデントを1つ下げて書く
{
	例↓
	template <typename Type>
		requires std::is_enum_v<Type>
	class EnumBitShift final
	{
	};
}
・型エイリアスはアッパーキャメルケースで、std::unordered_mapなどの宣言が長くなるものに使う
{
	例↓
	using SoundEffectMap = std::unordered_map<std::filesystem::path, std::shared_ptr<SoundEffect>>;
}
・マクロ名はFWK_をつけ、アッパースネークケースで書く
{
	例↓
	FWK_ASSERT_RETURN_IF
	FWK_DEFINE_TYPE_INFO
	FWK_REGISTER_FACTORY_METHOD
}
7.関数の命名について=========================================================================================================================================
・関数名はアッパーキャメルケース
・ライフサイクル系の関数
{
	初期化処理(InitializeではなくINIT)
	void INIT();

	コンフィグの読み込み・保存
	void LoadCONFIG();
	void SaveCONFIG() const;

	フレームの開始・終了
	void BeginFrame();
	void EndFrame  ();

	更新系
	void EarlyUpdate   ();
	void Update        ();
	void LateUpdate    ();
	void PostLateUpdate();

	作成・解放
	bool Create ();
	void Release();
}
・取得系の関数は「何を返すか」を名前に入れる
{
	REF : 参照を返す
	PTR : ポインタを返す
	VAL : 値を返す
	変更できる参照・ポインタを返すときはMutableをつける

	例↓
	const auto& GetREFAudioEngine        () const { return m_audioEngine; }
	      auto& GetMutableREFAudioEngine ()       { return m_audioEngine; }
	float       GetVALMasterVolume       () const { return m_masterVolume; }

	変数をそのまま返す               : Get
	探して返す(見つからない時がある) : Find
	計算・変換して返す               : Fetch
}
・ゲッターの名前はGet + 種類 + 変数名だけにする(Currentなどの言葉を足した別名のゲッターは作らない)
・セッターはSet + 変数名、引数名はa_set
{
	例↓
	void SetAssetFilePath(const std::filesystem::path& a_set) { m_assetFilePath = a_set; }
}
・値をセットするだけでなく処理もするならApply
{
	例↓
	void ApplyMasterVolume(const float a_volume);
}
・boolを返す判定の関数はIs、Can、Hasから始める
{
	例↓
	bool IsMinimized   () const;
	bool CanLoadFilePath() const;
}
8.変数の書き方について=======================================================================================================================================
・ローカル変数は型が右辺で分かるならautoで書く
{
	基本はconst auto&、書き換えるならauto&
	組み込み型(float、boolなど)をリテラルや計算で初期化するときは型名を書く

	例↓
	const auto& l_rootJson = Utility::LoadJsonFile(k_configFileIOPath);

	const float l_masterVolume = a_rootJson.value(k_masterVolumeJsonKey, Constant::k_defaultVolume);
}
・書き換えないローカル変数にはconstをつける
・クラスや構造体の初期化には波括弧初期化を使う
{
	例↓
	nlohmann::json l_rootJson = {};
}
・ポインタの場合は明示的にnullptrを代入する
{
	例↓
	Hoge* l_hoge = nullptr;
}
・&と*は型にくっつけて書く
{
	例↓
	const auto& l_hoge = ...;
	Hoge*       l_hoge = nullptr;
}
・変数の宣言が続くときは行間を開けずに、型と名前と=の位置を揃える
・const修飾子と型の位置を合わせない
{
	もしconst修飾子を持つ変数とそうでない変数を行間なしにくっつけて書く場合
	型の位置をconstに合わせるのではなくconstの後ろに続く型に合わせる
	理 : そうしたほうがconstなのかそうでないかが一目でわかるから

	例↓
	      auto& l_inputManager       = FWK::InputManager::GetInstance         ();
	const auto& l_keyboardController = l_inputManager.GetREFKeyboardController();
}
・関数の呼び出しが続くときは()の位置を揃える
{
	理 : ()の位置が揃うことで関数呼び出しの境界が一目で分かるから
	基本ルール : 関数名が長い方の()の位置に合わせる

	例↓
	auto& l_physicsManager  = FWK::Physics::PhysicsManager::GetInstance  ();
	auto& l_graphicsManager = FWK::Graphics::GraphicsManager::GetInstance();
	auto& l_audioManager    = FWK::AudioManager::GetInstance             ();

	l_graphicsManager.INIT();
	l_physicsManager.INIT ();
	l_audioManager.INIT   ();
}
・引数の数が同じ呼び出しが続くなら、2つ目以降の引数の位置も揃える
{
	例↓
	FWK_ASSERT_RETURN_VALUE_IF(!CreateCommandQueue(a_device), "コマンドキューの作成に失敗しました。", false);
	FWK_ASSERT_RETURN_VALUE_IF(!CreateFence(a_device),       "フェンスの作成に失敗しました。",         false);
}
・論理演算子を使う場合は改行する
{
	例↓
	const bool l_result = l_isB &&
	                      l_isC;
}
・ビット演算子を使う場合
{
	3つ以下なら改行しない
	4つ以上なら改行して縦に並べる
	理 : 演算子が縦に並ぶことでフラグの数と内容が一目で分かるから

	例↓
	const int l_flags = flagA |
	                    flagB |
	                    flagC |
	                    flagD;
}
・符号の位置は合わせる
{
	理 : 正の数か負の数かが瞬時にわかりやすいため
	※符号なしの数値は符号分のスペースを空けておく

	例↓
	static constexpr float k_soundEffectInstance2DMINPan = -1.0F;
	static constexpr float k_soundEffectInstance2DMAXPan =  1.0F;
}
・{}の初期化子は要素が4つ以上なら縦に並べ、3つ以下なら1行で書く
{
	例↓
	static constexpr TypeAlias::Math::Color k_defaultColor =
	{
		1.0F,
		1.0F,
		1.0F,
		1.0F
	};

	ImVec2 l_size = { 0.0F, 240.0F };
}
・数学の型はTypeAlias::Math::を使う
{
	例↓
	TypeAlias::Math::Vector3
	TypeAlias::Math::Matrix
}
9.数値リテラルについて=======================================================================================================================================
・floatには大文字のFをつけ、小数点以下を必ず書く
{
	例↓
	1.0F
	0.5F
}
・std::size_tやstd::uint64_tにはULL、std::uint32_tやUINTにはUをつける
{
	例↓
	static constexpr std::size_t k_initialIndex = 0ULL;
	static constexpr UINT        k_bufferCount  = 2U;
}
・意味のある数値は直接書かずに定数にする(マジックナンバーを書かない)
10.関数の引数について=========================================================================================================================================
・書き換えない引数にはconstをつける(値渡しの組み込み型も)
{
	例↓
	void ApplyMasterVolume(const float a_volume);
}
・8バイトより大きいもの(クラス、構造体、std::stringなど)はconst参照で渡す
・スマートポインタ
{
	基本はconst std::weak_ptr<T>&
	所有を共有して保持する引数だけconst std::shared_ptr<T>&

	例↓
	void AddEffectInstance(const std::weak_ptr<SoundEffectInstanceBase>& a_soundEffectInstanceBase);
}
・文字列はconst std::string&、ファイルパスはconst std::filesystem::path&
・引数の並びは変数の書き順(13章)と同じ
11.関数の宣言について=========================================================================================================================================
・隣接する関数で戻り値の後にスペーシングを挟んで関数名を書く場合は一番長い戻り値型に合わせる
{
	理 : 戻り値型と関数名の区切りが揃うことで可読性が高まるから
	※隣接する関数同士にのみ適用し、離している関数には適用しない

	例↓
	std::weak_ptr<SoundEffect> AddSoundEffect   (const std::filesystem::path&                  a_filePath);
	void                       AddEffectInstance(const std::weak_ptr<SoundEffectInstanceBase>& a_soundEffectInstanceBase);
}
・隣接する関数は()の位置、引数の型・名前、末尾のconstの位置を揃える
{
	例↓
	void StopAllSound  () const;
	void PauseAllSound () const;
	void ResumeAllSound() const;
}
・似た処理の関数は行間を開けずに並べ、違う処理なら1行開ける
・処理フローの両端に位置する関数は似ていても離す
{
	例↓
	void Deserialize(const nlohmann::json& a_rootJson);

	nlohmann::json Serialize() const;
}
・関数の引数が4個以上なら1引数1行で改行する(3個以下なら長くても改行しない)
{
	例↓
	void RequestSpriteDraw(const Math::Vector2&      a_pos,
	                       const Math::Vector2&      a_scale,
	                       const Texture&            a_texture,
	                       const Struct::SpriteRect* a_sourceRect);
}
・関数の書く順番
{
	大まかな処理順を優先
	void INIT      ();
	void LoadCONFIG();
	void Update    ();
	void SaveCONFIG() const;

	処理関数 → Is/Can/Has → Apply → Set → Fetch/Find → GetREF → GetMutableREF → GetPTR → GetMutablePTR → GetVAL
	.cppの定義もヘッダーと同じ順番で書く
}
・ゲッター・セッター・1行で済む処理はヘッダーに書き、ゲッターの戻り値はautoにする
{
	例↓
	const auto& GetREFAudioEngine() const { return m_audioEngine; }

	組み込み型を値で返す場合は型名を書く
	float GetVALMasterVolume() const { return m_masterVolume; }
}
12.クラスについて=============================================================================================================================================
・継承させないクラス・構造体には必ずfinalをつける
・クラスの書き方
{
	class Hoge final
	{
	private:

		そのクラスでしか使わない構造体、Enum、型エイリアスはprivateの一番上に書く
		using HogeStringMap = std::unordered_map<std::string, std::string>;

	public:

		 Hoge() = default;
		~Hoge() = default;

		公開する関数(関数の書く順番を参照)

	private:

		privateの関数

		定数

		メンバ変数

		マクロ(アクセス指定子を変える可能性があるので一番下)
	};

	アクセス指定子の次の行は必ず1行開ける
}
・コンストラクタとデストラクタはクラス名の位置を揃える
{
	理 : ~の位置が分かりやすくなり一瞬でコンストラクタ・デストラクタを見分けることができるから

	例↓
	 Hoge() = default;
	~Hoge() = default;

	基底クラス
	         HogeBase() = default;
	virtual ~HogeBase() = default;

	派生クラス
	 Hoge()          = default;
	~Hoge() override = default;
}
・メンバの初期化は2種類のどちらかにそろえる(混ぜない)
{
	理 : どちらで初期化されているかが一目で分かり、二重初期化にならないから

	コンストラクタが= defaultのとき : メンバの宣言で初期化する
	int m_a = 0;

	コンストラクタを.cppに書くとき : 全メンバを初期化子リストで初期化し、宣言には何も書かない
	int m_a;
}
・派生クラスの仮想関数にはoverrideをつける(virtualは書かない)
・コピーを禁止するときは4つまとめて書く
{
	例↓
	Hoge(const Hoge&)           = delete;
	Hoge(      Hoge&&) noexcept = default;

	Hoge& operator=(const Hoge&)           = delete;
	Hoge& operator=(      Hoge&&) noexcept = default;
}
・シングルトンのクラス
{
	class Hoge final : public Utility::SingletonBase<Hoge>
	{
	private:

		friend class SingletonBase<Hoge>;

		 Hoge();
		~Hoge() override;

	public:
		...
	};

	friendはシングルトンの基底クラスにだけ使う
}
・構造体で継承は使わない(共通部分があるならクラスにする)
・構造体はクラスの中に入れ子で書かずにDefinition/Structに書く
13.メンバ変数・定数の並び順について===========================================================================================================================
・定数は記憶域指定子の順に書く
{
	inline static const
	static constexpr
}
・メンバ変数は種類ごとに1行開けて、次の順に書く
{
	配列(std::vector、std::array、std::unordered_mapなど)
	スマートポインタ
	クラス・構造体
	組み込み型(std::uint64_t → float → bool の順)

	例↓
	SoundEffectMap m_soundEffectMap;

	std::vector<std::weak_ptr<SoundEffectInstanceBase>> m_soundEffectInstanceList;

	std::unique_ptr<DirectX::AudioEngine> m_audioEngine;

	DirectX::AudioListener m_audioListener;

	Converter::AudioManagerJsonConverter m_jsonConverter;

	float m_masterVolume;

	bool m_isAudioDeviceResetRequested;
	bool m_wasAudioDeviceReset;
}
・参照、ポインタ、値の順に書く
{
	int& 参照
	int* ポインタ
	int  値
}
14.コンストラクタの初期化子リストについて=====================================================================================================================
・:は)の後ろに書き、1メンバ1行で書く
・メンバの宣言と同じ順番、同じ空行の入れ方で書く
・続けて書くメンバは(の位置を揃える
・最後は{}を次の行に書く
{
	例↓
	FWK::AudioManager::AudioManager() :
		m_soundEffectMap(),

		m_audioEngine(nullptr),

		m_masterVolume(Constant::k_defaultVolume),

		m_isAudioDeviceResetRequested(false),
		m_wasAudioDeviceReset        (false)
	{}
}
15. .cppについて==============================================================================================================================================
・関数の定義はヘッダーの宣言と同じ順番で書く
・.hで隣接させた関数は.cppでも隣接させる(関数の間に空行を入れない)
・.hで1行開けた関数は.cppでも1行開ける
{
	例↓ .h
	void StopAllSound  () const;
	void PauseAllSound () const;

	void SaveCONFIG() const;

	例↓ .cpp
	void FWK::AudioManager::StopAllSound() const
	{
		～処理～
	}
	void FWK::AudioManager::PauseAllSound() const
	{
		～処理～
	}

	void FWK::AudioManager::SaveCONFIG() const
	{
		～処理～
	}
}
・コンストラクタとデストラクタは隣接させる
・.cppの関数定義は()の位置を合わせない
・処理のまとまりごとに1行開ける
16.ブレースとif文について=====================================================================================================================================
・関数・クラス・制御文の開きブレースは改行して次の行に書く
{
	例↓
	if (m_isAudioDeviceResetRequested)
	{
		m_isAudioDeviceResetRequested = false;
	}
}
・if、for、while、switchの後ろは1つ空白を開ける
・処理がreturnかcontinueだけのときは1行で書く(breakや他の処理はブロックにする)
{
	例↓
	if (!m_audioEngine) { return; }

	if (!l_soundEffectInstance) { continue; }
}
・連続してif文を書く、それがreturn文の場合()の位置を揃える
{
	例↓
	if      (m_isA)  { return false; }
	else if (m_isAB) { return false; }
}
・論理演算子をif文で使うなら改行し、符号の位置を揃える
{
	例↓
	if (!m_audioEngine->Update() &&
	     m_audioEngine->IsCriticalError())
	{
		...
	}
}
・if文の条件と中でしか使わない変数はif文の初期化文で宣言する
{
	例↓
	if (const auto& l_itr = m_soundEffectMap.find(a_filePath);
	    l_itr != m_soundEffectMap.end())
	{
		return l_itr->second;
	}
}
17.for文・switch文について===================================================================================================================================
・範囲for文を使い、ループ変数はconst auto&(書き換えるならauto&)
{
	例↓
	for (const auto& l_soundEffectInstanceWeak : m_soundEffectInstanceList)
	{
	}
}
・添字が必要なときはstd::size_tとULL、インクリメントは前置き
{
	例↓
	for (std::size_t l_index = 0ULL; l_index < l_count; ++l_index)
	{
	}
}
・caseの中はブロックにする
{
	例↓
	switch (a_type)
	{
		case Enum::Hoge::A:
		{
			～処理～
			break;
		}
		default:
		{
			break;
		}
	}
}
18.return文について===========================================================================================================================================
・returnの前は1行開ける(ブロックの最初の行なら開けない)
{
	例↓
	nlohmann::json l_rootJson = {};

	l_rootJson[k_masterVolumeJsonKey] = a_audioManager.GetVALMasterVolume();

	return l_rootJson;
}
・何も返さないときは{}で返す
{
	例↓
	if (!m_audioEngine) { return {}; }
}
19.コメントについて===========================================================================================================================================
・コメントは//を使い、//の後ろに空白を1つ開ける(/* */は使わない)
・コメントは日本語で書き、最後に「。」はつけない
・長くなるときは「、」で区切って次の行に続ける
{
	例↓
	// AudioEngine生成前にVolumeだけを設定された場合でも、
	// m_masterVolumeには値を保持しておく
}
・コメントは処理の上の行に書く(行の後ろには書かない)
・クラスの宣言(ヘッダー)には説明のコメントを書かない、処理の中身にコメントを書く
{
	理 : 宣言は名前で分かるようにして、なぜその処理をするのかは処理の近くに書いたほうが読みやすいから
	※ヘッダーに処理を書くUtilityやテンプレートは処理の中にコメントを書く
}
・何をするかだけでなく、なぜそうするのかを書く
{
	例↓
	// ヘッドホンやスピーカーの抜き差しなどによって
	// AudioEngineのReset要求が出ている場合、一度だけResetを試す
}
20.エラー処理について=========================================================================================================================================
・失敗したら処理を抜けるところはFWK_ASSERT_RETURN_IF / FWK_ASSERT_RETURN_VALUE_IFを使う
・メッセージは日本語で書き、最後に「。」をつける
{
	例↓
	FWK_ASSERT_RETURN_IF(!l_fence, "フェンスが作成されていません。");

	FWK_ASSERT_RETURN_VALUE_IF(!m_commandQueue, "コマンドキューが作成されていません。", false);
}
・HRESULTはFAILED()で判定する
{
	例↓
	if (FAILED(l_result)) { return false; }
}
21.定数について===============================================================================================================================================
・クラススコープの定数はstatic constexpr
・名前空間スコープの定数はinline constexpr
・ファイルパスなどconstexprにできないものはinline static const(名前空間スコープはinline const)
{
	例↓
	static constexpr float k_minMasterVolume = 0.0F;

	namespace FWK::Constant
	{
		inline constexpr float k_defaultVolume = 1.0F;
	}

	inline static const std::filesystem::path k_configFileIOPath = "CONFIG/Audio/AudioCONFIG.json";
}
・そのクラスでしか使わない定数はクラスのprivateに、複数のクラスで使う定数はDefinition/Constantに書く
・列挙子の値のためだけの定数は作らない
22.Jsonについて===============================================================================================================================================
・Jsonの読み書きはXxxJsonConverterクラスに分け、Converter/Json/に置く
・変換クラスはメンバに持つ(ローカルで作らない)
{
	例↓
	Converter::AudioManagerJsonConverter m_jsonConverter;
}
・読み込みはDeserialize、書き出しはSerialize
{
	例↓
	void Deserialize(const nlohmann::json& a_rootJson, AudioManager& a_audioManager) const;

	nlohmann::json Serialize(const AudioManager& a_audioManager) const;
}
・Jsonのキーは定数にし、名前はk_〜JsonKey、中身はアッパーキャメルケース
{
	例↓
	static constexpr std::string_view k_masterVolumeJsonKey = "MasterVolume";
}
・Deserializeの最初でnullか確認する
{
	例↓
	if (a_rootJson.is_null()) { return; }
}
23.スマートポインタについて===================================================================================================================================
・newは使わず、std::make_shared / std::make_uniqueで作る
・所有するものはshared_ptr / unique_ptr、参照するだけのものはweak_ptrで持つ
・weak_ptrはlockしてからnullptrか確認する
{
	例↓
	const auto& l_gameObject = a_gameObject.lock();

	if (!l_gameObject) { return false; }
}
・ComPtrはMicrosoft::WRL::を書かずにComPtr<>で書く
24.使わないもの===============================================================================================================================================
・this->
・Cスタイルのキャスト(static_castを使う)
・NULL(nullptrを使う)
・using namespace
・[[nodiscard]]
・noexcept(ムーブのdefaultだけ)
・ラムダ(std::ranges::any_ofなどの条件にだけ使う、それ以外は関数にする)
・自作の関数の戻り値に続けて関数を呼ぶこと(lock()だけはよい)
{
	例↓
	const auto& l_hierarchy = l_gameObject->GetREFHierarchy();
	const auto& l_parent    = l_hierarchy.GetREFParent().lock();
}
25.HLSLについて===============================================================================================================================================
・ファイル名の最後にシェーダーの種類をつける
{
	_VS : 頂点シェーダー
	_PS : ピクセルシェーダー
	_MS : メッシュシェーダー
	_AS : 増幅シェーダー
	_CS : コンピュートシェーダー
	共通の処理は.hlsliに書く
}
・.hlsliはインクルードガードを書く
{
	例↓
	#ifndef FINAL_COLOR_HLSLI
	#define FINAL_COLOR_HLSLI
	#include "../FullScreenTriangle.hlsli"

	～処理～

	#endif // FINAL_COLOR_HLSLI
}
・エントリーポイントはmain
・cbufferの名前はCB〜、中の変数とテクスチャ・サンプラーはg_
・16バイトにそろえるための変数はg_padding
{
	例↓
	cbuffer CBFinalColorPass : register(b0)
	{
		uint   g_sceneColorTextureSRVIndex;
		float3 g_padding;
	}

	SamplerState g_sceneColorSampler : register(s0);
}
・定数はstatic const、名前はk_、floatにはFをつける
{
	例↓
	static const float k_finalColorGammaBase = 2.2F;
}
・ローカル変数はl_、引数はa_で、書き換えない引数にもconstをつける
・C++と同じく宣言が続くときは型と名前と=を揃える
{
	例↓
	const float3 l_outputColorRGB = ConvertLinearColorToSimpleSRGB(l_linearColor.rgb);
	const float  l_outputAlpha    = ConvertFinalColorAlpha        (l_linearColor.a);
}
・テクスチャはResourceDescriptorHeap[添字]で取り出す
